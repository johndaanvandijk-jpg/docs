Die intelligente Solarnachführung

Autor: John van Dijk

Ziel: In diesem Modul fügen wir alles zusammen. Die Sensortechnik aus Modul 1 und der Mikrocontroller aus Modul 2 treffen auf die Mechanik aus Modul 3. Das Ziel ist eine Solarnachführung, die sich automatisch mit zwei Servomotoren über vier LDR-Sensoren zur hellsten Lichtquelle (Sonne) ausrichtet.

Lernziele
  • Steuerungslogik: If/Else-Bedingungen nutzen, um Entscheidungen zu treffen.
  • Regelungstechnik: Hysterese und Schwellenwerte verstehen, damit die Motoren nicht "zittern".
  • Systemintegration: Sensoren und Aktoren an einem Mikrocontroller (ESP32) kombinieren.

1. Die Hardware: Augen und Muskeln

Wir verwenden für unsere Nachführung vier LDRs (als "Augen") und zwei Servomotoren (als "Muskeln"), um die horizontale (Ost-West) und vertikale (Hoch-Runter) Achse zu steuern.

1.1. Anschluss eines LDRs (Spannungsteiler)

Bevor wir vier LDRs für die Nachführung zusammenschalten, schauen wir uns den Anschluss eines einzelnen LDRs an. Da der ESP32 nur Spannungen messen kann, verwenden wir einen Spannungsteiler.

Anschluss-Reihenfolge

Die genaue Funktionsweise des Spannungsteilers findest du ausführlich in Modul 1 (Fotometer), Sektion 1.2 erklärt.

Für den Anschluss gilt folgende Reihenfolge (in Reihe geschaltet):

  1. 3.3V (VCC) am ESP32
  2. LDR (Foto-Widerstand)
  3. Abgriff / Verbindungspunkt zum analogen Eingang (ADC-Pin)
  4. Festwiderstand (R1, z. B. 10 kΩ)
  5. GND (Masse) am ESP32

1.2. Das Prinzip der Steuerung: Vergleich von zwei LDRs

Um eine Achse (z.B. Ost-West) zu steuern, vergleichen wir zwei LDRs miteinander. Ist die linke Seite heller als die rechte, drehen wir den Servo nach links. Ist die rechte Seite heller, nach rechts. In dieser vereinfachten Version betrachten wir das Prinzip ohne Messfehler (Rauschen) und Hysterese (Threshold).

Interaktive Simulation: Einfacher LDR-Vergleich

Ziehe die Sonne auf der Bahn hin und her. Der Servo folgt sofort der helleren Seite (ohne Toleranzbereich).

Dieser einfache Helligkeitsvergleich lässt sich in C++ durch eine einfache If-Else-Bedingung umsetzen:

// Lese Analogwerte der beiden LDRs (0 bis 4095 beim ESP32)
int ldrL = analogRead(LDR_LINKS_PIN);
int ldrR = analogRead(LDR_RECHTS_PIN);

// Vergleiche die Werte und steuere den Servomotor
if (ldrL > ldrR) {
  // Links ist es heller -> Drehe den Servo schrittweise nach links
  servoPos = max(0, servoPos - 1);
} else if (ldrR > ldrL) {
  // Rechts ist es heller -> Drehe den Servo schrittweise nach rechts
  servoPos = min(180, servoPos + 1);
}

// Position an den Servo senden
servo.write(servoPos);
delay(50); // Kleine Pause zur Beruhigung

1.3. Der physische Aufbau: 2 Achsen, 4 LDRs

Um die Solarzelle sowohl horizontal (Ost-West) als auch vertikal (Hoch-Runter) auszurichten, benötigen wir zwei Servomotoren und vier LDRs. Die vier Sensoren werden in einer 2x2-Matrix angeordnet und durch ein Trennkreuz voneinander abgeschottet. So wirft die Sonne je nach Einfallswinkel einen Schatten auf bestimmte Sensoren, wodurch deutliche Helligkeitsunterschiede entstehen.

Stromversorgung der Servos

Servomotoren benötigen beim Anlaufen oft viel Strom. Wir schließen beide Servos an den VIN-Pin (5V) des ESP32 an. Die Steuersignale kommen von zwei digitalen GPIO-Pins.

Hinweis: Sollte der ESP32 bei der Bewegung beider Servos abstürzen oder neustarten, reicht der Strom des USB-Anschlusses eventuell nicht aus.

2. Die Steuerungslogik: Helligkeitsvergleich und Hysterese

Damit der ESP32 weiß, wohin er die Solarzelle drehen muss, vergleicht er die Helligkeitswerte der gegenüberliegenden Sensoren. Ist es zum Beispiel links heller als rechts, muss der horizontale Servo nach links drehen.

Probier es selbst aus: Ziehe die Sonne auf dem Halbkreis und beobachte, wie die LDR-Werte reagieren!

Das Problem: Zittern

Wenn du das Rauschen aktivierst und die Sonne fast genau in der Mitte positionierst, siehst du, wie die Werte springen. Der Servo würde ununterbrochen zittern. Erhöhe den Schwellenwert (Threshold): Der Servo bewegt sich erst, wenn der Helligkeitsunterschied groß genug ist.

❌ Ohne Threshold (Zittern)

int diff = ldrL - ldrR;

if (diff > 0) {
  servo.write(pos + 1); // Nach links
} else if (diff < 0) {
  servo.write(pos - 1); // Nach rechts
}

✅ Mit Threshold (Ruhig)

int diff = ldrL - ldrR;
int threshold = 50;

if (abs(diff) > threshold) {
  if (diff > 0) {
    servo.write(pos + 1);
  } else {
    servo.write(pos - 1);
  }
}

3. Der Programmcode

Mit diesem fertigen Sketch steuert der ESP32 beide Achsen der Solarnachführung vollautomatisch an. Über den Seriellen Monitor kannst du die aktuellen Sensorwerte und die Servopositionen in Echtzeit mitverfolgen.

Vorbereitung in der Arduino IDE / PlatformIO

  1. Öffne in der Arduino IDE den Bibliotheksverwalter (Strg + Umschalt + I / Cmd + Umschalt + I).
  2. Suche nach ESP32Servo (von Kevin Harrington / John K. Bennett) und installiere die neueste Version.
  3. Wähle als Board dein ESP32-Board aus (z. B. Adafruit ESP32 Feather oder ESP32 Dev Module) und stelle die Baudrate im Seriellen Monitor auf 115200 Baud.

Gesamter Arduino Sketch

#include <Arduino.h>
#include <ESP32Servo.h>

// Servo Pins
const int pinServoHoriz = 12;
const int pinServoVert = 13;

// LDR Pins (ADC1)
const int ldrTopLeft = 32;
const int ldrTopRight = 33;
const int ldrBotLeft = 34;
const int ldrBotRight = 35;

Servo servoHoriz;
Servo servoVert;

// Startposition der Servos (Mitte)
int posHoriz = 90;
int posVert = 90;

// Konfiguration der Nachführung
const int toleranz = 100;   // Deadband: Verhindert ständiges Zittern
const int schrittweite = 1; // Gradzahl der Bewegung pro Durchlauf
const int messPause = 50;   // Umbenannt zur Vermeidung des Namenskonflikts

void setup() {
  Serial.begin(115200);

  // ESP32 Timer für Servos allozieren
  ESP32PWM::allocateTimer(0);
  ESP32PWM::allocateTimer(1);
  ESP32PWM::allocateTimer(2);
  ESP32PWM::allocateTimer(3);

  // Servos anbinden
  servoHoriz.setPeriodHertz(50);
  servoVert.setPeriodHertz(50);
  servoHoriz.attach(pinServoHoriz, 500, 2400); 
  servoVert.attach(pinServoVert, 500, 2400);

  // Auf Startposition fahren
  servoHoriz.write(posHoriz);
  servoVert.write(posVert);
}

void loop() {
  // 1. Werte der LDRs einlesen
  int valTL = analogRead(ldrTopLeft);
  int valTR = analogRead(ldrTopRight);
  int valBL = analogRead(ldrBotLeft);
  int valBR = analogRead(ldrBotRight);

  // 2. Durchschnittswerte der Achsen berechnen
  int avgTop = (valTL + valTR) / 2;
  int avgBot = (valBL + valBR) / 2;
  int avgLeft = (valTL + valBL) / 2;
  int avgRight = (valTR + valBR) / 2;

  // 3. Differenzen berechnen
  int diffVert = avgTop - avgBot;
  int diffHoriz = avgLeft - avgRight;

  // 4. Vertikale Ausrichtung anpassen (Logik: Kleinerer Wert = heller)
  if (abs(diffVert) > toleranz) {
    if (avgTop < avgBot) {
      posVert += schrittweite; // Oben ist heller, kippe nach oben
    } else {
      posVert -= schrittweite; // Unten ist heller, kippe nach unten
    }
  }

  // 5. Horizontale Ausrichtung anpassen (Logik: Kleinerer Wert = heller)
  if (abs(diffHoriz) > toleranz) {
    if (avgLeft < avgRight) {
      posHoriz -= schrittweite; // Links ist heller, drehe nach links
    } else {
      posHoriz += schrittweite; // Rechts ist heller, drehe nach rechts
    }
  }

  // 6. Mechanische Grenzen einhalten
  posVert = constrain(posVert, 0, 180);
  posHoriz = constrain(posHoriz, 0, 180);

  // 7. Servos bewegen
  servoVert.write(posVert);
  servoHoriz.write(posHoriz);

  // 8. Debug-Ausgabe für den Serial Monitor
  Serial.printf("LDR Werte -> Oben-Links: %d | Oben-Rechts: %d | Unten-Links: %d | Unten-Rechts: %d\n", valTL, valTR, valBL, valBR);
  Serial.printf("Servo Pos -> Vertikal: %d | Horizontal: %d\n", posVert, posHoriz);
  Serial.println("--------------------------------------------------");

  delay(messPause);
}

4. Auswertungstool: Statisch vs. Nachgeführt

Mit diesem Auswertungstool können Schülerinnen, Schüler und Lehrkräfte den Tagesverlauf und den Energieertrag einer statischen Solarzelle direkt mit einer zweiachsig nachgeführten Solarzelle vergleichen. Überprüft die Machbarkeit und findet heraus, ob der Mehrertrag den Eigenverbrauch der Motoren rechtfertigt!

Messaufbau: Spannung, Strom & Leistung der Solarzelle messen

Um die elektrische Leistung (P = U · I) einer Solarzelle zu bestimmen, kann man die Spannung nicht einfach im Leerlauf abgreifen, da ohne Verbraucher kein Strom fließt (I = 0 A ⇒ P = 0 W).

Das Messprinzip (Ohm'sches Gesetz)

  1. Die Solarzelle wird über einen Lastwiderstand (RL, z. B. 47 Ω bis 100 Ω) geschlossen.
  2. Der ESP32/Arduino misst die abfallende Spannung U parallel zum Lastwiderstand an einem analogen ADC-Eingang.
  3. Der Strom I berechnet sich automatisch über das Ohm'sche Gesetz: I = U / RL.
  4. Die Leistung P ergibt sich direkt zu:
    P = U2 / RL

Auswertung & Reflexionsfragen für den Unterricht

Aufgabe 1: Kurvenverlauf vergleichen
Begründe, warum die Leistungskurve der statischen Solarzelle eine Glockenkurve (Sinus-/Cosinus-Form) aufweist, während die nachgeführte Zelle über fast den gesamten Tagesverlauf eine nahezu konstante Helligkeit sieht.

Aufgabe 2: Eigenverbrauch & Skalierungseffekt
Vergleiche ein kleines Schulmodell (z. B. 1 Watt Solarzelle, Servos verbrauchen 0,15 Watt) mit einem industriellen Solarpark (z. B. 1 MegaWatt Modulfeld, Motoren verbrauchen 500 Watt). Warum ist die Solarnachführung beim Schulmodell oft netto negativ, bei Großanlagen jedoch wirtschaftlich sinnvoll?

Aufgabe 3: Mechanische & Wirtschaftliche Kriterien
Nenne mindestens zwei Gründe, warum in der Praxis für Hausdächer und Balkonkraftwerke fast ausschließlich statische PV-Anlagen verbaut werden, obwohl nachgeführte Anlagen mehr Brutto-Energie liefern.

Musterlösung / Lehrkräfte-Hinweis

  • Zu 1: Die statische Zelle sieht nur mittags einen senkrechten Lichteinfall (&cos;(0°) = 1). Morgens und abends trifft das Licht in flachem Winkel auf. Die nachgeführte Zelle dreht sich stets rechtwinklig zur Sonne.
  • Zu 2: Der Eigenverbrauch der Elektronik und Motoren skaliert nicht linear mit der Modulgröße. Bei Miniatur-Anlagen macht der Motorverbrauch einen großen Prozentsatz aus. Bei Großanlagen machen die Nachführ-Motoren nur einen Bruchteil des Gesamtertrags aus.
  • Zu 3: Mechanischer Verschleiß, Windanfälligkeit/Sturmschäden, hohe Anschaffungskosten für Mechanik/Motoren und regelmäßige Wartungskosten.
